# Жёсткие правила проекта

Эти правила — постоянные и обязательные. Они соблюдаются автоматически,
без вопросов к пользователю и без необходимости спрашивать «есть ли они?».
Ассистент и вся автоматика всегда исходят из того, что база, загруженные
файлы и данные существуют и должны находиться в рабочем состоянии.

## 1. НИЧЕГО НИКОГДА НИКУДА НЕ ПРОПАДАЕТ

Загружаемые пользователями файлы (аватарки партнёров, фото активностей,
фото слайдера hero) и любые данные должны надёжно храниться. Ни один
загруженный пользователем файл не должен теряться при пересоздании сервера,
пересборке или деплое.

- Загруженные файлы лежат в `public/uploads/`.
- Папка `public/uploads/` НЕ исключена из git и не должна исключаться.
- Авто-коммит `public/uploads/` в git выполняется при каждом деплое
  и может выполняться по расписанию — это гарантирует восстановление файлов
  даже при полной потере сервера.
- Периодический бэкап загружаемых файлов создаётся в отдельную папку
  `backups/uploads/` (архивы `uploads-<дата>.tar.gz`), которую деплой
  не удаляет и не перезатирает.
- Данные пользователей (клиенты, партнёры, агенты, активности, заказы,
  отзывы, настройки) хранятся в DynamoDB и защищены проверкой/починкой схемы
  БД (см. правило 2).

### Механизмы соблюдения

- Скрипт `npm run upload:backup` (`scripts/backup-uploads.ts`):
  - создаёт архив `backups/uploads/uploads-<дата>.tar.gz` из `public/uploads/`;
  - сохраняет последние 30 бэкапов, старые удаляются;
  - авто-коммитит изменения в `public/uploads/` в git, если они есть.
- Скрипт вызывается автоматически из `deploy.sh` перед деплоем.

## 2. БАЗЫ ВСЕГДА В РАБОЧЕМ СОСТОЯНИИ

При каждом деплое и при запуске автоматически проверяется:

- доступность БД (DynamoDB / Yandex Cloud Document API);
- схема всех таблиц (ключи и GSI) сверяется с кодом;
- прогоняются миграции;
- исправляются несоответствия: пересоздание таблиц с неверным ключом,
  добавление недостающих GSI.

### Механизмы соблюдения

- Скрипт `npm run db:check` (`scripts/check-db.ts`):
  - проверка доступности БД (health);
  - проверка и починка схемы всех таблиц (`scripts/verify-schema.ts`);
  - прогон миграций (`scripts/migrate.ts`).
- Скрипт автоматически запускается из `deploy.sh` как часть процесса деплоя
  (через `docker compose exec -T app npm run db:check`).

## 3. НИКОГДА НЕ СПРАШИВАТЬ «ЕСТЬ ЛИ ОНИ?»

Ассистент и автоматика всегда исходят из того, что база, загруженные файлы
и данные существуют и должны быть в рабочем состоянии. Вместо вопроса
о наличии чего-либо состояние проверяется и приводится в рабочее состояние
автоматически:

- доступность БД проверяется через `db:check`;
- наличие загруженных файлов и их сохранность — через `upload:backup`;
- отсутствующие таблицы, ключи и GSI создаются/исправляются автоматически.

## Обязанности при работе с проектом

- Не удалять и не отключать автоматику (`db:check`, `upload:backup`,
  вызовы из `deploy.sh`).
- Не добавлять `public/uploads/` в `.gitignore`.
- Не удалять папку `backups/uploads/` и не исключать её из-под проверки.
- Любые изменения схемы таблиц вносить в `lib/schema.ts`
  (пакет `packages/shared`), после чего прогонять `db:check`.
- Соблюдать правила из `AGENTS.md` (DynamoDB — единственная система
  хранения, никаких Postgres/Redis/файлового хранилища как базы).
